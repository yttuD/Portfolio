# Plan de optimización del perfil GitHub

> Documento operativo del titular de la cuenta; no publicar datos de contacto sin su autorización.

## 1. Perfil personal

Crear un repositorio público llamado **`yttuD`** bajo la cuenta **`yttuD`** (nombre completo: `yttuD/yttuD`). GitHub mostrará su README en la portada del perfil. Copiar allí [GITHUB_PROFILE_README.md](GITHUB_PROFILE_README.md) y eliminar su nota editorial final.

**Bio sugerida (menos de 160 caracteres):**

```text
Full Stack Developer | React · TypeScript · Next.js · Node.js · Python | SaaS, business systems & AI integrations
```

**Location:** `Argentina · Open to remote opportunities`

**Website:** usar la URL de producción de Vercel **solo después de verificar que esté pública y funcional**. Mientras tanto, `https://github.com/yttuD/Portfolio`.

**Contacto:** configurar una dirección profesional pública solo si se autoriza. No inferir ni publicar teléfonos o correos de la cuenta.

## 2. Repositorios fijados (pinned)

1. [Portfolio](https://github.com/yttuD/Portfolio) — sitio profesional, bilingüe y responsive.
2. [clinica-san-martin-tpi](https://github.com/yttuD/clinica-san-martin-tpi) — muestra de arquitectura Full Stack con documentación técnica.
3. Añadir otras muestras **solo tras** verificar licencia, seguridad, pruebas y autorización para publicarlas.

No fijar forks ajenos como proyectos originales. No promocionar repositorios de uso exclusivamente personal. El código fuente de un SaaS comercial puede permanecer privado y mostrarse mediante un estudio de caso.

Los repositorios fijados se configuran desde **GitHub Profile → Customize your pins**. La conexión disponible no ofrece una acción para automatizar este cambio.

## 3. Plantilla para repositorios destacados

Para cada uno incluir:

- Una frase de problema/solución por encima de badges o tooling.
- Capturas **reales**, sin datos personales ni información sensible.
- Tecnologías verificadas en `package.json` / configuración.
- Módulos implementados; diferencia clara entre planificación, desarrollo y producción.
- Instrucciones locales reproducibles, variables de entorno de ejemplo y scripts de prueba.
- Arquitectura, decisiones y tradeoffs.
- Límites conocidos, contribución propia y autoría compartida cuando corresponda.
- Enlace a demo únicamente después de comprobar su disponibilidad.

## 4. Orden de trabajo

- **Ahora:** terminar Vercel, conectar sitio público, elegir 2 repositorios fijados, completar bio.
- **Siguiente:** incorporar capturas verificadas de Rendo y turnos, acordar un email profesional, terminar CV definitivo.
- **Posterior:** preparar una demostración sanitizada de IA local/TransAI y un repositorio público adicional técnicamente sólido.

## 5. Privacidad

El repositorio de portafolio no necesita secretos ni un backend. No abrir por defecto repositorios de clientes, herramientas privadas o productos comerciales. Al cambiar la visibilidad de un repositorio comprobar dependencias de despliegue y el historial de Git antes de autorizar la operación.
